## Implementation order (v1.0.0 worktree)

Execution is ordered by expected performance impact, using the audit's measured
allocation costs ahead of speculative cache/layout gains. The numbered proposals
below retain their original identifiers and historical source observations;
implementation must verify those observations against the current source.

| 2 | Proposal 4: batch/Extend pipeline, write-through, Entry leaf hints | Preconstructed updates 6 → 3 allocations; guarded updates 264 → 0; Entry avoids a second descent | Complete |
| 3 | Proposal 2: shared traversal, cached promoted roots, opportunistic slot swing | Shared root/descent/B-link kernels; cached roots give zero parent hops; native and Miri coverage | Complete |

Correctness prerequisites take precedence within each change. Proposal 2's
`LayerAnchor` remains conditional on the profiling trigger in §3.2; PERF-12/13
are evaluations, not authorization to change WIDTH without evidence. Existing
fixes (including reverse snapshot validation, sentinel test wiring, dependency
cleanup, and real tracing) are credited only after source verification.
Completed within step 1: full-live-set rebuild sizing and eliminating unused
preallocation reduced the existing churn probe from 42 to 6 allocations and
71,584 to 20,560 requested bytes (20 cycles). Raw ownership now uses a single
144-byte header (the actual baseline was 168 bytes with AtomicU64 metadata),
without suffix-count RMWs. Unused suffix APIs and `PermutationProvider` are
removed as explicitly requested. Split destinations reserve the entire incoming
suffix set, including a new right-side entry: the allocation probe confirms 3 →
0 reallocations. Header-only initialization avoids 516 redundant bytes of stores
(default capacity). Proposal 3 is complete; native tests, both suffix features,
strict Clippy, and Miri cover the changed paths.

Completed within step 2: one owning `BatchEntry` pipeline, shared empty-leaf
initialization, direct guarded results, and unwind-safe suffix retirement.
`Extend`/`FromIterator` now use the same pipeline in bounded, borrowed-key
chunks, without collecting unused old values. A local release probe on 20,000
keys measured random construction at 1.92 ms versus 2.12 ms for single inserts,
and ascending construction at 0.87 ms versus 1.57 ms (seven-round medians; these
are workload-specific measurements). Entry now captures a guarded leaf hint in
the shared lookup kernel, validates it under lock, and uses the existing slot
update and initialization helpers before falling back to full traversal.
Immediate occupied and vacant mutations perform zero further root descents,
including promoted and maximum-depth layers. Vacant-to-occupied fallback uses
write-through (the allocation probe drops from 3 to 0). Native/Miri tests cover
invalidation by slot reuse, layer conversion, splits, version repetition, and
sublayer retirement; the Loom model covers lock/version revalidation only. The
isolated 20,000-key update probe measured 2.00 ms for Entry versus 3.18 ms for
two traversals with short keys, and 2.50 ms versus 4.28 ms for promoted-layer
keys (seven-round release medians). Guarded single-key insertion now dispatches
write-through before boxing and returns `Option<ValueRef<'g, P::Value>>`, the
user-approved semver-breaking API change. Its 260-update allocation probe drops
from 264 to 0; non-Clone boxed values return guarded borrows, and
primitive/inline old values are owned snapshots. Native, compile-fail, and Miri
tests cover these contracts. Proposal 4 is complete.

Completed within step 3: guarded point operations, forward/reverse scans,
printing and sublayer GC share `tree::traversal::resolve_layer_root`. Both scan
contexts retain the resolved root on initial positioning and retries, including

policies pass zero-hop read, held-parent-lock progress, multi-height promotion,
and subsequent GC tests under Miri. A Loom model checks that refresh cannot

Tier 1 is complete. The conditional LayerAnchor tier is deferred: zero-hop
caching works for the tested multi-height layers, and no workload measurement
establishes the required sustained parent-lock miss bottleneck.

Completed within step 4: insert search now uses one three-way unrolled kernel
with a `SINGLE_LAYER` specialization. The unreachable WIDTH>16 binary branches

## 1. Executive Architectural Assessment

Across `src/` (**101 files, 44,901 total LOC / 25,159 non-test LOC**), the
remediation commits (`93e65eb..da74a75`) resolved the initial audit's point
defects. However, a line-by-line verification of the current codebase (`HEAD` =
`d2a9d68`) against earlier drafts of this document and
[`SystemAudit.md`](SystemAudit.md)
establishes three core findings:

1. **Several items in earlier drafts of `ArchitectureProposals.md` have already
   landed** in `9ffacd5..da74a75` and have been moved to the **Already Landed**
   ledger (§1.1) so that every active proposal below targets **only open work**.
2. **State-machine multiplication has already caused post-remediation drift —
   including 4 newly uncovered OCC and cursor-corruption bugs in
   `src/tree/range/reverse_ctx.rs` (§2.1).** Because forward scans
   (`forward_ctx.rs`), reverse scans (`reverse_ctx.rs`), and batch scans
   (`batch_common.rs`) maintain separate copies of the OCC slot-read protocol,
   fixes applied to forward and batch scans in `a2869ff` and `e3eed9f` were
   never mirrored into three reverse-scan slot readers (`try_emit_generic`,
   `find_prev_single_layer`, `try_emit_slot_reverse`) or `advance_prev_leaf`.
3. **Two earlier proposal designs (`Propagation` parent-leaf locking in Proposal
   2 and speculative `lock_for_insert` in Proposal 6) contained protocol flaws**
   when checked against the live lock-ordering and `NodeVersion` invariants in
   `src/`. Sections 3 and 7 replace those designs with deadlock-free,
   weak-memory-sound protocols.

#### Four Newly Uncovered Correctness Defects in `ReverseScanCtx` (`src/tree/range/reverse_ctx.rs`)

Because `forward_ctx.rs`, `reverse_ctx.rs`, and `batch_common.rs` maintain
separate copies of the OCC slot-read state machine, the OCC fixes applied to
forward and batch scans in `a2869ff` and `e3eed9f` left **four live defects** in
`reverse_ctx.rs`:

1. **`ReverseScanCtx::try_emit_generic` mutates `cursor_key` before
   reading/validating the value and lacks a post-read OCC check
   ([`src/tree/range/reverse_ctx.rs:705-747`](../src/tree/range/reverse_ctx.rs#L705-L747)):**
   - At line 706, `if leaf.version().has_changed(version)` is checked **before**
     reading `leaf.ksuf(slot)` (line 718) and **before**
     `E::emit_value(leaf, slot, key_len)` (line 731).
   - Worse, at lines 711–728, `self.cursor_key.assign_store_ikey(slot_ikey)`,
     `self.cursor_key.assign_store_suffix(suffix)`,
     `self.cursor_key.assign_store_length(key_len)`, and
     `self.flags.clear_upper_bound()` are executed **before**
     `E::emit_value(leaf, slot, key_len)` and without any post-load
     `has_changed(version)` check:
     ```rust
     // src/tree/range/reverse_ctx.rs:706-746 — BUGGY ORDERING
     if leaf.version().has_changed(version) {
         self.stack.set_ki(ki);
         return ReverseStepResult::Retry;
     }
     self.cursor_key.assign_store_ikey(slot_ikey); // <-- mutates cursor_key BEFORE value load!
     if slot_keylenx == KSUF_KEYLENX {
         if E::NEEDS_SUFFIX_KEY {
             if let Some(suffix) = leaf.ksuf(slot) {
                 let suffix_len = self.cursor_key.assign_store_suffix(suffix);
                 self.cursor_key.assign_store_length(IKEY_SIZE + suffix_len);
             } else {
                 self.cursor_key.assign_store_length(IKEY_SIZE);
             }
         }
         key_len = self.cursor_key.len();
     } else {
         self.cursor_key.assign_store_length(key_len);
     }
     self.flags.clear_upper_bound(); // <-- clears upper_bound flag BEFORE value load!

     let Some(output) = E::emit_value(leaf, slot, key_len) else {
         self.stack.set_ki(ki - 1); // <-- cursor_key & flags are now corrupted!
         return ReverseStepResult::Continue;
     };
     // <-- NO post-load leaf.version().has_changed(version) check!
     ```
   - Compare this with `ForwardScanCtx::find_next_generic`
     ([`src/tree/range/forward_ctx.rs:475-506`](../src/tree/range/forward_ctx.rs#L475-L506))
     and `BatchCtx::process_batch_keyed`
     ([`src/tree/range/batch_common.rs:437-465`](../src/tree/range/batch_common.rs#L437-L465)),
     both of which load `output` and `suffix` first, verify
     `!leaf.version().has_changed(version)`, and only then commit to
     `self.cursor_key`.

2. **`ReverseScanCtx::find_prev_single_layer` mutates `cursor_key`, `flags`, and
   `stack` before `load_value(slot)` and never checks `has_changed(version)`

### 2.2 Proposed Unified Range Architecture & Concrete Code Blueprint

#### A. Immediate Fix for `ReverseScanCtx` via Shared Validated Slot-Snapshot Kernel (`try_snapshot_slot`)

Extract a single, direction-agnostic slot reader in `src/tree/range/helper.rs`
that enforces the
**Read → Validate `has_changed(version)` → Commit `cursor_key`** invariant
across every scan mode (`ScanEmit`, single-layer, values-only, and batch):

```rust
// In src/tree/range/reverse_ctx.rs:702-747 — Corrected `try_emit_generic`
#[inline(always)]
fn try_emit_generic<E: ScanEmit<P>>(
    &mut self,
    leaf: &LeafNode15<P>,
    version: u32,
    slot: usize,
    slot_ikey: u64,
    slot_keylenx: u8,
    ki: isize,
) -> ReverseStepResult<P, E::ValuesOnly> {
    // 1. Load value FIRST (drops redundant `is_value_empty_relaxed` precheck, PERF-08).
    let prelim_len: usize = if slot_keylenx == KSUF_KEYLENX {
        IKEY_SIZE
    } else {
        slot_keylenx as usize
    };
    let Some(output) = E::emit_value(leaf, slot, prelim_len) else {
        if leaf.version().has_changed(version) {
            self.stack.set_ki(ki);
            return ReverseStepResult::Retry;
        }
        self.stack.set_ki(ki - 1);
        return ReverseStepResult::Continue;
    };

    // 2. Read suffix slice BEFORE mutating `self.cursor_key`.
    let suffix_opt: Option<&[u8]> = if slot_keylenx == KSUF_KEYLENX && E::NEEDS_SUFFIX_KEY {
        leaf.ksuf(slot)
    } else {
        None
    };

    // 3. Validate leaf version AFTER reading both value and suffix!
    if leaf.version().has_changed(version) {
        self.stack.set_ki(ki);
        return ReverseStepResult::Retry;
    }

    // 4. Commit to `cursor_key`, `flags`, and `stack` ONLY after OCC validation succeeds.
    self.cursor_key.assign_store_ikey(slot_ikey);
    let key_len: usize = if slot_keylenx == KSUF_KEYLENX {
        if E::NEEDS_SUFFIX_KEY {
            let suffix_len: usize = suffix_opt
                .map_or(0, |s| self.cursor_key.assign_store_suffix(s));
            let total: usize = IKEY_SIZE + suffix_len;
            self.cursor_key.assign_store_length(total);
            total
        } else {
            self.cursor_key.len()
        }
    } else {
        self.cursor_key.assign_store_length(prelim_len);
        prelim_len
    };

    self.flags.clear_upper_bound();
    self.flags.mark_cursor_emitted();
    self.stack.set_last_ikey(slot_ikey);
    self.stack.set_ki(ki - 1);

    ReverseStepResult::Emit(E::finish_snapshot(output, key_len))
}
```

#### B. Why Naive Parent-Leaf Locking During Sublayer Split Is Deadlock-Prone and Incomplete

When a sublayer leaf `L0` splits (`Propagation::propagation_loop` at
[`src/tree/split/propagation.rs:86-114`](../src/tree/split/propagation.rs#L86-L114)),
`RootCreation::promote_layer_root_leaves`
([`src/tree/split/root_creation.rs:92-120`](../src/tree/split/root_creation.rs#L92-L120))
creates a new internode `R1` with `L0` as left child and `L1` as right child.
Because `L0` is a sublayer root (`L0 != tree_root`), `propagation_loop` does
**not** update the upper-layer parent leaf's slot (`parent_leaf.values[slot]`),
which continues to point at `L0`. Every subsequent operation descending into
that sublayer must climb `L0.parent -> R1 -> ... -> Rn` via
`maybe_parent_generic`
([`src/tree/generic.rs:1098-1129`](../src/tree/generic.rs#L1098-L1129))
or `climb_layer_root`
([`src/tree/range/traversal.rs:61-75`](../src/tree/range/traversal.rs#L61-L75))—which
currently appears at **9 separate call sites**.

An earlier draft proposed passing `(parent_leaf_ptr, parent_slot)` into
`Propagation` and locking `parent_leaf` during `create_new_layer_root` to
overwrite the slot with `R1`.
**Source verification shows that approach has three fatal flaws:**
1. **Lock-Order Inversion (Deadlock Hazard):** Sublayer GC
   (`Coalesce::try_remove_sublayer` at
   [`src/tree/coalesce.rs:606-666`](../src/tree/coalesce.rs#L606-L666)) and
   layer creation (`src/tree/generic/layer.rs`) lock `parent_leaf` **first** and
   then lock the sublayer nodes (**top-down**: `parent_leaf -> sublayer`).
   During `propagation_loop`, the splitting thread already holds `left_lock` on
   `L0` (and `L1` is split-locked). Attempting to lock `parent_leaf` from inside
   `propagation_loop` acquires locks **bottom-up** (`sublayer -> parent_leaf`).
   Even a non-blocking `try_lock` fails under contention on hot prefixes—the
   exact case where sublayers promote!
2. **Higher-Height Sublayer Root Splits (`height > 0`) Have No `parent_leaf`
   Context:** When the sublayer grows again and `R1` (an internode at
   `height == 0`) splits into `R2` (`height == 1`) via
   `RootCreation::promote_layer_root_internodes`
   ([`src/tree/split/root_creation.rs:123-151`](../src/tree/split/root_creation.rs#L123-L151)),
   the split begins at a sublayer leaf `Lk` that may be multiple siblings away
   from `L0`. The thread splitting `Lk` did not necessarily descend through
   `parent_leaf` in the same step or may have traversed a B-link sibling, and
   `R1` has no back-pointer to `(parent_leaf, parent_slot)`.
3. **Invariant Coupling with `Coalesce::try_remove_sublayer`:**
   `try_remove_sublayer`
   ([`src/tree/coalesce.rs:514-565, 622-666`](../src/tree/coalesce.rs#L514-L565))
   relies on the parent slot pointing to a valid node in the sublayer from which
   it can both climb to `sublayer_root` (for `teardown_layer`) and walk the leaf
   B-link chain. If the parent slot is overwritten with an internode `R1`,
   `all_leaves_empty` must descend `child(0)` from `R1` to locate the leftmost
   leaf `L0`.

### 3.2 Proposed Two-Tier Architecture

#### Tier 1 (Immediate, Zero-Lock-Inversion): Unified Descent Kernel + Opportunistic Slot Swing

1. **Unify `climb_layer_root` and `maybe_parent_generic` into One Helper
   (`resolve_layer_root`):**
   - Consolidate `maybe_parent_generic`
     ([`src/tree/generic.rs:1098-1129`](../src/tree/generic.rs#L1098-L1129)) and
     `climb_layer_root`
     ([`src/tree/range/traversal.rs:61-75`](../src/tree/range/traversal.rs#L61-L75))
     into a single `#[inline]` function
     `resolve_layer_root(ptr: *const u8, guard: &LocalGuard<'_>) -> *mut u8`.
2. **Unify `reach_leaf_for_scan` with `reach_leaf_concurrent_generic` (`RNG-09`,
   `OCC-04`):**
   - Replace `traverse_internodes_for_scan`
     ([`src/tree/range/traversal.rs:99-152`](../src/tree/range/traversal.rs#L99-L152))
     with a call to `reach_leaf_concurrent_generic` (which already checks
     `inode.version().is_deleted()` and handles concurrent root splits),
     followed by the scan B-link advance.
   - Return `(leaf_ptr, resolved_root)` from `reach_leaf_for_scan` so
     `ScanStackElement` / `BackStackElement` immediately caches `resolved_root`
     (`PERF-07`).
3. **Make `Coalesce::all_leaves_empty` Root-Agonistic & Swing Parent Slots
   Opportunistically:**
   - In [`src/tree/coalesce.rs:510-565`](../src/tree/coalesce.rs#L510-L565),
     find `leftmost_leaf` by descending `child(0)` from `sublayer_root` until
     `node.version().is_leaf()`, rather than casting the raw parent-slot pointer
     to `*const LeafNode15<P>`.
   - Once `all_leaves_empty` derives `L0` from `sublayer_root`, any thread that
     observes `resolved_root != raw_layer_ptr` after `resolve_layer_root` (when
     no sublayer lock is held, preserving top-down lock order!) can attempt a
     non-blocking `if let Some(lock) = parent_leaf.version().try_lock()` to
     verify
     `parent_leaf.ikey_relaxed(slot) == layer_ikey && parent_leaf.keylenx_relaxed(slot) >= LAYER_KEYLENX && parent_leaf.load_layer_raw(slot) == raw_layer_ptr`
     and call `unsafe { parent_leaf.store_layer(slot, resolved_root) }`. Because
     this happens **outside** any sublayer lock, it strictly respects the
     `parent_leaf -> sublayer` lock hierarchy and works for arbitrary-height
     promotions (`L0 -> R1 -> R2 -> Rn`)!

#### Tier 2 (Long-Term Target Aligned with [`ARCHITECTURERefined.md` §4.3](ARCHITECTURERefined.md#L155-L185)): `LayerAnchor` Indirection

If workload profiling shows multi-level sublayer promotions (`R1 -> R2 -> R3`)
under heavy contention where `try_lock` on `parent_leaf` frequently misses:
- Allocate a 16-byte
  `LayerAnchor { root: AtomicPtr<u8>, leftmost_leaf: AtomicPtr<LeafNode15<P>> }`
  per sublayer.
- The parent leaf slot points immutably to `LayerAnchor`.
- `RootCreation::promote_layer_root_leaves` and `promote_layer_root_internodes`
  atomically `Release`-store the new sublayer root into `anchor.root` in $O(1)$
  without touching `parent_leaf`, while `anchor.leftmost_leaf` gives
  `try_remove_sublayer` direct $O(1)$ access to the B-link leaf chain.

- **Performance:** Eliminates repeated $O(h)$ parent-pointer climbs on every

- **Correctness & Maintainability:** Unifies 5 B-link/internode descent routines

### 4.2 Proposed Design & Concrete Code Blueprint

#### A. Replace `UnsafeCell<Vec<u8>>` with Direct Raw Allocation Ownership in `SuffixBag`
Eliminate `data: UnsafeCell<Vec<u8>>` completely. Let `SuffixBag` own its heap
buffer directly through
`(data_ptr: AtomicPtr<u8>, capacity: AtomicUsize, used: AtomicUsize)`:

```rust
pub struct SuffixBag {
    slots: [AtomicU32; WIDTH], // 60B: packed (offset: u32, len: u16)
    pad: u32,                  // 4B alignment padding
    data_ptr: AtomicPtr<u8>,   // 8B: immutable once published!
    capacity: AtomicUsize,     // 8B: immutable once published!
    used: AtomicUsize,         // 8B: monotonically increasing under leaf lock
} // Size drops from 112 bytes to 88 bytes (-24 bytes); zero UnsafeCell!

impl Drop for SuffixBag {
    fn drop(&mut self) {
        let ptr: *mut u8 = *self.data_ptr.get_mut();
        let cap: usize = *self.capacity.get_mut();
        if !ptr.is_null() && cap > 0 {
            // SAFETY: `ptr` and `cap` were allocated from `Vec<u8>` with capacity `cap`
            // and all `u8` elements are trivially drop-safe (`len = 0`).
            unsafe {
                drop(Vec::from_raw_parts(ptr, 0, cap));
            }
        }
    }
}
```

- `try_append_suffix(&self, slot, suffix)` writes strictly to
  `data_ptr.add(old_used..old_used + suffix.len())`, updates
  `self.used.store(new_used, RELAXED)`, and publishes
  `self.slots[slot].store(meta.pack(), WRITE_ORD)` (Release). There is
  **no `UnsafeCell` and no `Vec::set_len`** anywhere.

#### B. Preserve Slack After `merge_old_external_perm` (`PERF-02`) and Pre-Size Split Bags (`PERF-09`)
- In `drain_and_rebuild`
  ([`src/policy/suffix_ops.rs:344-354`](../src/policy/suffix_ops.rs#L344-L354)),
  compute total required bytes **including** active slots in `old_external`
  *before* allocating `new_external`, and reserve
  `max(total_active_bytes * 2, total_active_bytes + 512)` capped at `u16::MAX`
  so the newly published external bag always has append slack for subsequent
  updates/inserts.
- In `SuffixBag::assign_in_place`
  ([`src/suffix.rs:621-635`](../src/suffix.rs#L621-L635)) (used on unpublished
  bags during split/init), grow capacity geometrically
  (`(required * 2).max(INITIAL_CAPACITY)`) instead of exact-sizing
  `required = self.used() + suffix.len()`.

#### C. Header-Only `InlineSuffixBag::init_at_zero` (`PERF-11`)
In
[`src/suffix/inline.rs`](../src/suffix/inline.rs)
and
[`src/policy/embedded_suffix.rs:188-196`](../src/policy/embedded_suffix.rs#L188-L196),
replace `StdPtr::write(bag_ptr, InlineSuffixBag::new())` with:

```rust
#[inline(always)]
pub unsafe fn init_at_zero(bag_ptr: *mut Self) {
    // SAFETY: Caller (`LeafNode15::init_at`) already zeroed the entire struct via `write_bytes`.
    // `size`, `suffix_count`, `pad`, and `data: [u8; CAPACITY]` are valid at all-zeroes.
    // Only the 60-byte `slots` array needs `EMPTY_PACKED` (`0xFFFF_0000`).
    unsafe {
        let slots_ptr: *mut [AtomicU32; WIDTH] = StdPtr::addr_of_mut!((*bag_ptr).slots);
        slots_ptr.write([const { AtomicU32::new(Self::EMPTY_PACKED) }; WIDTH]);
    }
}
```
This eliminates **516 bytes of redundant stores (44.8% of the 1,152-byte leaf)**
on every `InlinePolicy` leaf allocation.

#### B. `NodeVersion::stable()` Fast Path & Why Speculative `lock_for_insert` Must Be Avoided (`PERF-18`, [`src/nodeversion.rs:331-395`](../src/nodeversion.rs#L331-L395))
1. **`PERF-18` (`NodeVersion::stable()` at
   [`src/nodeversion.rs:331-337`](../src/nodeversion.rs#L331-L337)):**
   ```rust
   pub fn stable(&self) -> u32 {
       let v: u32 = self.value.load(Ordering::Relaxed);
       if (v & DIRTY_MASK) == 0 {
           fence(Ordering::Acquire); // <-- 2 instructions (`ldr` + `dmb ish`) on aarch64!
           return v;
       }
       self.stable_slow()
   }
   ```
   Meanwhile, `NodeVersion::try_stable()`
   ([`src/nodeversion.rs:389`](../src/nodeversion.rs#L389)) already uses
   `self.value.load(Ordering::Acquire)`! Replacing
   `load(Relaxed) + fence(Acquire)` in `stable()` with
   `self.value.load(Ordering::Acquire)` emits a single `ldar` instruction on
   `aarch64` on every clean internode and leaf read.
2. **Why Naive `lock_for_insert` (Setting `LOCK_BIT | INSERTING_BIT` on Initial
   Lock Acquisition) Is Counterproductive on Speculative Locks:**
   - Earlier drafts proposed replacing `version.lock()` + `lock.mark_insert()`
     with a single `lock_for_insert()` that sets `LOCK_BIT | INSERTING_BIT` in
     the initial CAS.
   - **Critical Subtlety Verified in
     [`src/nodeversion.rs:117-128, 413-432`](../src/nodeversion.rs#L117-L128):**
     - `has_changed(old)` checks `(old ^ current) > LOCK_BIT`. When a writer
       acquires `lock()` (`LOCK_BIT` only), concurrent OCC readers on the same
       leaf **do not abort** while the writer performs `validate_post_lock`
       ([`src/tree/generic/insert.rs:526`](../src/tree/generic/insert.rs#L526)),
       `validate_membership`
       ([`insert.rs:556`](../src/tree/generic/insert.rs#L556)), or
       `find_usable_slot` (`Found` update or `Retry`).
     - Furthermore, in `LockGuard::drop`
       ([`src/nodeversion.rs:117-128`](../src/nodeversion.rs#L117-L128)), the
       insert version counter `vinsert` is incremented on unlock
       **if and only if `INSERTING_BIT` is set**. If `validate_post_lock` fails
       and the lock is dropped without mutating the leaf, unlocking `LOCK_BIT`
       leaves the version unchanged and causes zero reader retries.
     - Additionally, an initial
       `compare_exchange_weak(..., Ordering::Acquire, ...)` does **not** act as
       a `Release` barrier preventing subsequent relaxed slot writes from
       floating before `INSERTING_BIT` on weak memory (`OCC-03`);
       `mark_insert()`'s `fence(Ordering::Release)`
       ([`src/nodeversion.rs:640`](../src/nodeversion.rs#L640)) is required
       specifically to order `INSERTING_BIT` before subsequent relaxed
       slot/suffix writes.
